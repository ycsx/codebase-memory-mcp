# 每日 100 美元 Token 预算下的研发交付计划

> 状态：执行排期草案
> 预算约束：每天模型使用费用上限 100 美元
> 对应路线图：[Codebase Memory MCP 产品研发路线图](PRODUCT_ENGINEERING_ROADMAP.md)
> 文档专项：[文档知识图谱与代码知识融合规划](DOCUMENT_KNOWLEDGE_GRAPH_PLAN.md)

## 1. 排期结论

建议采用“14 周核心产品 + 6 周高级能力”的 20 周计划：

- 第 1-2 周：可信响应契约。
- 第 3-4 周：`build_context`。
- 第 5-6 周：`review_change` 和 PR 评论模式。
- 第 7-9 周：统一远程 MCP Server 团队试点。
- 第 10-12 周：文档知识图谱及代码关联。
- 第 13-14 周：项目健康度及可视化。
- 第 15 周：覆盖率接入和精准测试推荐。
- 第 16 周：Vue/Webpack 定向迁移规划。
- 第 17 周：重构雷达。
- 第 18 周：图谱版本差异和架构漂移。
- 第 19 周：OpenTelemetry 与离线故障解释。
- 第 20 周：数据血缘研究、整体稳定化和路线复盘。

第 14 周结束时应形成第一个完整产品闭环：

```text
可信图谱
  -> build_context
  -> review_change
  -> 统一远程 MCP
  -> 文档与代码双层知识
  -> 项目健康度可视化
```

如果预算、人工验收或真实项目数据不足，应在第 14 周形成稳定版本，后 6 周功能顺延，不压缩可信、安全和质量验证。

|---|---:|

如果周末也持续进行模型密集型研发，则理论硬上限会变为每周 700 美元、20 周 14,000 美元。本计划不依赖这部分额外预算。

### 2.2 为什么不能直接换算固定 Token 数

100 美元能够购买的 Token 数取决于：

- 使用的模型和服务层级。
- 输入、输出和缓存 Token 单价。
- 上下文长度。
- 是否命中提示词缓存。
- 是否使用多个并行 Agent。

因此执行时按每日实际美元消耗控制，不把预算换算成一个会随模型价格变化而失真的固定 Token 数。

### 2.3 每周建议分配

| 用途 | 比例 | 每周计划金额 |
|---|---:|---:|

逐周计划额在 350-450 美元之间调配，20 周合计 8,000 美元。高风险周的实际使用允许接近 500 美元硬上限，但不能连续两周依赖满额才能完成正常目标。

## 3. 执行规则

### 3.1 周节奏

建议每周采用以下节奏：

- 周一：确认上一周门槛、冻结本周 Schema 和黄金样本。
- 周二至周三：核心实现和单元测试。
- 周四：集成测试、安全测试、UI 或跨平台验证。
- 周五：回归、文档、演示和是否进入下一周的决策。
- 周末：只运行流水线、soak、基准或人工复核，原则上不启动新的模型密集型功能。

### 3.2 Token 使用规则

- 先用图谱、编译器、测试和本地脚本缩小问题，再让模型读取最小证据。
- 同一失败不要反复传入完整日志，只传新增和关键差异。
- 大文件和大型 diff 先结构化切分，再按目标读取。
- 高风险设计使用一次独立审查，避免实现完成后大规模返工。
- 并行 Agent 只用于边界清晰、可独立验证的任务。
- 每天保留至少 15%-20% 预算用于回归失败和意外问题。
- 当天消耗达到 80 美元时停止扩大范围，优先完成测试和交付记录。

### 3.3 阶段门槛

以下能力未达到验收标准时，不得用后续功能掩盖问题：

- 可信元数据未稳定，不能进入 PR 门禁和健康度评分。
- ACL 未完成越权测试，不能开放团队远程服务。
- 文档关系精确率不足，不能进入高严重度漂移提示。
- 覆盖率未接入，不能宣称推荐的是最小测试集合。
- graph generation 未稳定，不能解释健康度趋势和架构漂移。

验收门槛：

- Schema 可以承载 `build_context`、`review_change` 和健康度。
- 每种 freshness 和 coverage 状态至少有一个黄金测试。
- 明确哪些原子工具只警告，哪些组合工具必须拒绝确定性结论。

预算：计划 350 美元，本周硬上限 500 美元。

### 第 2 周：可信层实现

主要目标：把第 1 周契约接入图谱 generation 和组合分析底座。

交付物：

- generation 持久化和原子读取。
- Git commit、工作区状态、生成时间和覆盖摘要。

- stale、partial 和 truncated 回归测试。
- 工具清单一致性检查进入 CI。

验收门槛：

- 相同 generation 输出稳定一致。
- 明显过期的图谱不会被高层工具标记为确定通过。
- 已知解析缺口和截断能够进入顶层响应。
- 老索引能够安全打开、迁移或明确要求重建。

预算：计划 450 美元，本周硬上限 500 美元。

## 5. 第 3-4 周：`build_context`

### 第 3 周：上下文编译核心

主要目标：完成不依赖 UI 的确定性上下文包。

交付物：

- 输入 Schema：任务、目标、diff、预算、证据等级。

- Token 预算估算和裁剪器。

验收门槛：

- 输出 Token 不超过预算 10%。
- 同一源码范围不重复出现。
- 模糊目标返回候选，不擅自选择。
- 每条关系结论具有可回溯证据。

预算：计划 450 美元，本周硬上限 500 美元。

主要目标：证明组合工具优于固定原子工具流程。

- `scout/analysis/audit` 三档证据预算。
- 上下文预览 UI。
- Token 使用、召回和裁剪原因展示。
- Agent 使用提示和文档。

验收门槛：

- 关键符号召回优于固定三次原子工具基线。
- UI 能看到被选证据和被裁剪数量。
- 低覆盖和过期索引状态持续可见。
- 重复运行的结果排序具有可接受稳定性。

预算：计划 350 美元，本周硬上限 500 美元。

## 6. 第 5-6 周：`review_change`

### 第 5 周：PR 风险分析核心

主要目标：把 diff、影响、复杂度和边界分析统一成评审结果。

交付物：

- merge-base 和 diff 去重规则。
- 公共 API、路由、配置和 Schema 变化识别。
- 直接、间接和跨服务影响。
- 复杂度、循环和架构边界规则。
- 关联测试和文档候选。
- `pass/warn/block/unknown` 结果 Schema。

验收门槛：

- 同一 diff 在 CLI 和 MCP 中得到一致结果。
- `unknown` 不会被解释为 `pass`。
- 每个阻断候选携带规则 ID 和证据。
- 图谱过期时拒绝无条件通过。

预算：计划 450 美元，本周硬上限 500 美元。

### 第 6 周：CI 评论、Owner 和评审 UI

主要目标：形成可在真实 PR 中试运行的评论模式。

交付物：

- GitHub/GitLab 中至少一个评论适配器。
- CODEOWNERS 和显式 Owner 解析。
- 评审 UI：风险、影响、测试、文档、Owner 和规则。
- 规则命中、确认、忽略和误报遥测。
- 评论模式，不默认阻断合并。

验收门槛：

- 推荐评审人具有 CODEOWNERS 或明确历史证据。
- 评论中的每个风险可回到源码或图路径。
- 同一 commit 重试不会重复刷评论。
- 真实项目完成至少 10 个 PR 的影子评审。

预算：计划 350 美元，本周硬上限 500 美元。

里程碑 M2：PR 风险门禁进入评论试点。

## 7. 第 7-9 周：统一远程 MCP Server

### 第 7 周：多身份和权限模型

主要目标：将单一 Token 升级为 principal/key/policy。

交付物：

- 用户、CI 和管理员主体模型。
- API Key 哈希、Key ID、创建、撤销和轮换。
- 项目、工具 Profile、源码读取、索引和删除 Scope。
- 授权后 `tools/list` 裁剪。
- `list_projects` 权限过滤。
- 越权和侧信道测试。

验收门槛：

- 无权主体不能看到项目名称、数量或源码片段。
- 参数修改不能绕过项目 ACL。
- 缓存和审计不会泄露 Token。
- 管理权限与 MCP 查询权限分离。

预算：计划 450 美元，本周硬上限 500 美元。

### 第 8 周：项目目录和索引调度

主要目标：统一管理本地和 Git 项目，并安全更新 generation。

交付物：

- 项目目录 Schema 和管理 API。
- Git URL、分支、同步策略、Owner 和 policy。
- 异步索引任务和状态查询。
- 同项目、commit、模式任务去重。
- 上一代图谱继续提供查询，新 generation 完成后原子切换。
- Git 拉取错误和索引错误分离。

验收门槛：

- 重复索引请求只产生一个实际任务。
- 查询不会读取半成品图谱。
- 失败任务可重试且保留上一代可用图谱。
- Git 凭证不进入项目数据库和日志。

预算：计划 400 美元，本周硬上限 500 美元。

### 第 9 周：管理 UI、限流和服务验证

主要目标：达到团队内网试点条件。

交付物：

验收门槛：

- 无跨会话和跨主体数据串扰。
- 查询 P95 在基准机器上低于 1 秒。
- 审计能够对应 principal、项目、工具和状态。
- API Key 只在创建时显示一次。

预算：计划 450 美元，本周硬上限 500 美元。

5. 自动化重构和代码修改。

不能通过削减测试、安全或可信元数据来换取更多功能数量。
